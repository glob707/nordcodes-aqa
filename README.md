# API-автотесты сервиса /endpoint

## Что проверяется

Сайт выполняет три основные функции:

1. Вход: пользователь вводит логин и пароль, сайт проверяет их и сохраняет данные.
2. Действие: после входа пользователь выполняет действие, которое уходит на внешний сервер.
3. Выход: пользователь выходит, данные удаляются.

## Какие инструменты используются

* Java 17: язык тестов.
* Maven: сборка и запуск.
* JUnit 5: тестовый фреймворк.
* REST Assured: запросы и проверки API.
* WireMock: заглушка внешнего сервера.
* Allure: отчёты.
* Awaitility: ожидание асинхронных условий.

## Что нужно для запуска

Нужны:

* Установленные Java 17 и Maven 3.9.
* JAR проверяемого приложения.
* Allure CLI для отчёта (по желанию).

## Как настроить

1. Положите JAR в папку app или передайте путь через -Dapp.jar.
2. Больше ничего настраивать не нужно: тесты сами поднимут WireMock и приложение на свободных портах.
3. Параметры лежат в test.properties, любой можно переопределить через -D.

## Как запустить

Запуск основных тестов:

```
mvn clean test
```

Прогон занимает около 30 секунд: 69 тестов, все зелёные. Лог приложения пишется в target/application.log.

Тесты на известные дефекты помечены тегом `defect` и в основной прогон не входят — они падают намеренно, ожидаемый результат в них взят из документации, а приложение ведёт себя иначе. Отдельный запуск:

```
mvn test -Pdefects
```

Там 8 тестов, и все падают, пока дефекты D-01–D-03 не исправлены.

## Найденные дефекты

| ID | Что не так | Тест |
|---|---|---|
| D-01, Critical | Документация разрешает в token символы `A-Z0-9`, а приложение принимает только `0-9A-F`. Токен `GHIJ…` по документации валиден, но получает 400 | `RequestValidationTest.tokenWithLettersAfterFIsAccepted` |
| D-02, Normal | `GET`/`PUT`/`PATCH`/`DELETE` возвращают 500 вместо 405 | `HttpProtocolTest.unsupportedMethodIsRejected` |
| D-03, Normal | Неподдерживаемый Content-Type возвращает 500 вместо 415 | `HttpProtocolTest.unsupportedContentTypeIsRejected` |
| D-04, Minor | Неизвестный путь возвращает 500 вместо 404 | нет, путь вне контракта |
| D-05, Major | При неверном `X-Api-Key` приложение пишет в лог ожидаемый секрет; без `-Dsecret` принимает ключ по умолчанию `qazWSXedc` | нет, проверяется по логу |

Мелкие замечания: при неверных token и action сразу сообщение говорит только об action; `Accept: text/plain` даёт 406 с пустым телом; тексты ошибок валидации token зависят от локали сервера и раскрывают регулярное выражение; отказ внешнего сервиса при входе (401/403) клиент получает как 500.

Вопросы к владельцу требований: какой алфавит token верен; считать ли 3xx от внешнего сервиса успехом (сейчас токен сохраняется при 302/304); должен ли action быть регистронезависимым (`login` отклоняется, ` LOGOUT ` с пробелами принимается); допустимо ли передавать параметры в строке запроса.
